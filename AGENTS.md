# TSUGI desktop repository instructions

Before changing TSUGI UI or assessing release readiness, read [the mandatory visual standard](docs/tsugi-visual-standard.md). It is the non-negotiable maintainer directive for every visual element. Harbor governs Watch presentation; TSUGI retains its approved identity. Equivalent settings, fonts, colors, sidebars and controls must be cohesive across every section.

Read [the active P0–P5 recovery roadmap](docs/tsugi-recovery-roadmap.md), [the design system](docs/tsugi-design-system.md), [design integration](docs/design-integration.md), HANDOFF.md and PROGRESS.md. Follow relevant repository conventions in [CLAUDE.md](CLAUDE.md). The latest explicit maintainer direction and mandatory standard supersede conflicting historical visual notes. Preserve functional playback, data, security and existing release gates.

Use the [living visual acceptance ledger](docs/tsugi-visual-audit.md) alongside the original screenshot matrix. Audit every user-visible surface and applicable state; correct inconsistencies at their shared source; record rendered and interaction evidence, repair commits and remaining blockers. Green CI is not visual acceptance. No visually deficient candidate may be treated as accepted or packaged. Update handoff/progress after meaningful work and continue the next authorized roadmap task rather than stopping for routine check-ins.
