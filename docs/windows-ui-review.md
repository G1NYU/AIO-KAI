## Lyrics timing acceptance gate

The implemented repair is in `lib/music/lyrics.ts`, `app/music/use-track-lyrics.ts` and `app/music/lyrics-panel.tsx`, with provider recording type retained through library/history. Its focused tests cover exact title/artist selection, actual-duration/album agreement, video and conflicting-timeline warnings, bounded session-only corrections, manual line matching without audio seeking, corrected line seeking/highlighting, reset and recording/source isolation. Controlled native-bridge, original PCM and imported Studio browser cases passed the final correction before integration.

Independent review found catalogue duration being presented as actual duration while the decoder still reported zero. The corrected implementation keeps decoder duration separate from the display estimate, resets it for each playback, and leaves timing unconfirmed until valid metadata arrives. The focused native-duration-zero, later-valid-metadata and small-duration-jitter cases passed; the final source review found no remaining actionable P1/P2 issue. A passing suite cannot confirm the timestamps against the exact recording in the user's screenshot. That requires listening to the same recording; an unconfirmed video remains unconfirmed until the user explicitly aligns it. No universal offset is assumed. See [lyrics timing](music-lyrics.md) for the controls and limits.
